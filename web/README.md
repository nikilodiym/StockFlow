# WareGo — вебпанель адміністратора

Вебінтерфейс відтворено за SVG з архіву «WareGo ТЗ_основний _ 1 (4).zip». Основний еталон — 1440 × 1024. Оригінальні логотип та іконки навігації збережено як SVG, Roboto завантажується локально. Мобільний застосунок і сервер цією зміною не змінюються.

## Запуск

З кореня StockFlow: `npm run dev`. З папки web: `npm run dev`.

У звичайному режимі відкривається форма входу. Потрібен запущений Django API на `http://127.0.0.1:8000`. Vite проксіює `/api`; іншу адресу можна задати через `VITE_API_URL`. Для production налаштуйте reverse proxy `/api` або адресу API під час збірки.

- `/?preview=1` — перегляд екранів на прикладах з макетів, без запитів до сервера.
- `/?preview=1&role=manager` — вигляд менеджера.
- `#dashboard`, `#catalog`, `#documents`, `#users`, `#warehouses`, `#reports` — розділи.

Зміни у preview зберігаються тільки в sessionStorage поточної вкладки та не впливають на серверні дані. Для чистого перегляду відкрийте адресу в новій вкладці.

## Реалізовано

Вхід і помилка входу; дашборд; товари, категорії та одиниці виміру; документи й фільтри; акаунти, матриця прав та вигляд запитів на відновлення; склади; аналітика; форми створення й редагування; імпорт та експорт CSV; підтвердження видалення, блокування та виходу; створений акаунт; панелі деталей документа, конфлікту та журналу синхронізацій; сповіщення; вигляд менеджера. Таблиці, пошук, пагінація, вибір складу та модальні вікна працюють. На вузьких екранах доступне згорнуте меню та прокручування таблиць.

Серверні операції використовують наявні endpoints products, categories, units, barcodes, imports, documents, warehouses, users, stocks, notifications та sync. JWT оновлюється через refresh; паралельні запити використовують один refresh. Списки завантажуються з урахуванням усіх сторінок API. Помилки збереження залишають форму відкритою.

## Межі поточного API

- API не надає погодинну статистику сканувань і поточну чергу записів на пристроях. У робочому режимі показано відсутність даних; у preview — значення з макетів.
- Модель складу не містить місткості. Це поле доступне у preview, а в робочому режимі заблоковане. Менеджер призначається через акаунт і membership.
- Префікс категорії в робочому режимі визначається за SKU, окремого серверного поля немає.
- Endpoints запитів на відновлення та видачі тимчасового PIN адміністратором відсутні. Новому акаунту генерується тимчасовий пароль; його показано одноразово. Пароль чинного користувача можна змінити через акаунти.
- Сервер вирішує конфлікт для документа цілком. Вибір джерела в порівнянні синхронізований для всіх позицій.

## Перевірки

`npm test` — 8 тестів API-клієнта: JWT refresh, паралельне оновлення, завершена сесія, вхід без старого JWT, пагінація, multipart CSV, помилки валідації, CSV з українськими символами.

`npm run build` — production-збірка Vite. Браузерна перевірка виконується на 1440 × 1024 та 390 × 844. Живі операції з виробничою базою під час перевірки не виконуються.
